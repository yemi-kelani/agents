pr-reviewer

Design decisions

A LangGraph agent that reviews a pull request diff and posts findings to GitHub. Its model is not an API client, it is a coding CLI running as a subprocess. Fifteen choices that follow from that, and what each one costs.

START→ should_review→ diff_analyzer→ critique→ END Two nodes behind a gate. The gate can also route straight to END, and records why.

The model layer

Everything below follows from one choice at the bottom of the stack.

llm.py

A CLI subprocess is the chat model

ShellChatModel implements LangChain's BaseChatModel by shelling out to codex or bob. That buys a coding agent with filesystem access for free.

Cost No native tool calling, no token accounting, no conversation state. The class documents all three rather than hiding them.

tool_loop.py

The tool loop is hand written

bind_tools raises, so the protocol is text. The model replies with {"tool": ...} or {"answer": ...} and the loop dispatches it. A node picks the task and the tools, the loop runs the turns.

Cost Prose, fences and stray objects have to be tolerated by the parser instead of by the SDK.

tools/explore.py

Exploration is one sub-agent, not four file tools

There is no read, list or grep. There is explore_codebase, which spawns a second CLI in the repo and returns a digested answer.

Cost Another subprocess per question, in exchange for a history that stays small. The full history is re-sent on every step.

llm.py, parsers.py

Read the file the CLI wrote, parse stdout only as a fallback

--output-last-message is authoritative. When parsing is unavoidable, only item.completed payloads count as answers.

Cost A second code path to keep alive. Worth it: a top-level message belongs to an error event, and reading one would report a crash as the review.

Control flow

One graph, run by CI and by a terminal, under a budget it enforces itself.

agent.py

The review gate is a node, not a conditional edge

State mutated inside a routing function does not reach the graph result, so the skip reason has to be returned as a state update and routed on afterwards.

Cost An extra node and an explicit path_map, since the router is opaque to LangGraph.

agent.py, review.py

One graph, two front ends

create_graph(gated=False) drops the double-post check for the terminal client, which prints instead of posting and has nothing to double-post. Everything else is shared.

Cost One flag whose meaning lives in a docstring rather than in the type.

main.py, nodes/diff_analyzer.py

Budgets nest, and the numbers are written down

The process stops itself at 1500s, under the workflow's 30 minutes, because a job killed by the harness leaves no comment and no exit code. Inside it, the fan-out worst case is spelled out as segments over concurrency, times attempts, times timeout.

Cost Four constants that have to be changed together.

nodes/diff_analyzer.py

Diff segments overlap and never reassemble

Each segment repeats 1000 characters of the one before it, so a hunk landing on a boundary is readable in full somewhere. Past twelve segments the review is explicitly partial.

Cost Some duplicate summarization. The prompt tells the model overlap is expected.

Failure

The reviewer runs unattended, so every failure has to be legible from the outside.

tool_loop.py, nodes/diff_analyzer.py

Failure is data, not an exception

Unknown tool, bad arguments, a tool that raises, unparseable JSON, a spent budget: all come back as messages. abatch(return_exceptions=True) keeps eleven segment summaries when one fails.

Cost Errors can be quietly absorbed, so truncation and failed segments are written into the output text.

main.py, github_client.py

Exit codes encode why, not what was found

0 means a review ran, clean or not, because findings ship in the PR comment. 2 is misconfiguration, 1 is failure. GitHubUnavailable exists so "GitHub was down" (retry the job) never looks like "this is wired wrong" (fix it).

Cost A second exception class and three skip reasons the graph has to carry.

nodes/critique.py, settings.py

Sentinels, never empty values

An empty reply is how the model layer reports that the CLI died, so a clean review has to say NO FINDINGS. Unlimited reviews needs its own token, because an unparseable env value falls back to the default rather than to None. Secrets get or None, since an empty string reaches the provider as a confusing auth error.

Cost Three magic values a reader has to learn.

github_client.py, models.py

An invisible marker makes reruns safe

Every posted review carries an HTML comment that renders as nothing. That is how a later run recognizes its own work, which is why a clean review is still posted, and why counting reviews raises instead of returning a possibly wrong zero.

Cost A paginated read before every review, and a 60k character cap on the body so an oversized post cannot 422 away a finished review.

Boundaries

What each part is allowed to see, import, and print.

llm.py

Child processes get an allowlist, not a copy of the environment

The codex process never sees the bob key. Proxy variables are added back deliberately, because the allowlist is exactly what would otherwise cut off the network on a proxied runner.

Cost Any variable a CLI needs has to be named. A wrong env_key means the child gets no credential at all.

log.py, utilities.py

Secrets are scrubbed on the finished log line

Redaction happens after formatting, because keys arrive through interpolated arguments and tracebacks rather than through format strings. utilities takes the stdlib logger by name to avoid a cycle while still inheriting the scrubbing handler.

Cost A regex that has to keep up with new token prefixes.

parsers.py, models.py, tests/

Layers are enforced by what a module may import

parsers returns plain dicts so it never sees graph types. format_review lives beside the model it formats, keeping github_client transport only. Types sit in models because a node importing the graph would be a cycle. Tests drive an injected request= seam instead of patching urllib.

Cost Findings get built twice, once as dicts and once as models.

llm.py, parsers.py

Comments record evidence, not intent

The credential comment carries the probe output from CLI 0.153.4 and the two error shapes that separate "no key sent" from "key rejected". parse_bob is marked unverified. Several comments name the bug the current shape prevents.

Cost Comments go stale against a version number, which is the point: they are checkable.

Run it

# review a pull request, print findings, post nothing
cd pr-reviewer/src && python review.py owner/repo#3

# a local range, or a saved diff
python review.py main..HEAD
python review.py saved.diff

# what CI runs: reads the env, posts once, exits 0 / 1 / 2
python main.py
